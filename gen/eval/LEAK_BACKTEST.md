# 泄漏门回测（不调 LLM）

命令：`uv run python -m tbsgen.backtest --out eval/leak_backtest_final`；留出集加 `--set holdout81`。
结果：`leak_backtest_final/{summary.json,results.jsonl}`、`leak_backtest_final_holdout81/`。
每题平均耗时 1.5 s。L3 自省在 Docker 里运行（`--network none`、数据只读），只有含公开 `.py` 的题才需要跑。

## 样本

| 集合 | 题数 | 来源 | 用途 |
|---|---|---|---|
| 正例 | 7 | 人工复审丢弃的 6 道黑盒 Oracle 泄漏题（`st-corpus410/harbor/<id>`），以及协方差可反解题 `doi-196db5a3b2c31394` 的修复前版本 | 召回 |
| 对照 | 231 | `tbs-simple-final-20261031/harbor-v07-new244` 中复审通过的 230 题，加上 196db 的修复后版本 | 误报（**样本内**：规则是对着这批题调的） |
| 留出 | 81 | `runs/harbor-v06`（早期 81 题，调规则时没看过） | 误报（样本外） |

## 需要注意的地方

- **调参偏差**：v1 规则在 231 个对照上误报 108 个，按误报类型改了 3 轮才到 0/231。所以 0/231 是样本内数字，样本外的估计以留出集的 1/81 为准（样本量小，置信区间宽）。
- **L1b（题面声明“不许读/opaque/内部状态”）在 6 道黑盒题上都命中**，是最强的单项信号。它是规则判定：只要题面靠一句话保护某个公开文件，就判泄漏，因为 agent 在容器里是 root，这句话保护不了任何东西。fa4fa8 只靠这一条命中（真值在 `problems.npz` 里，但字段名不同，而且 x* 要靠优化才能得到，数值扫描找不到）。
- **L2 用“同名回显”豁免**：真值目录里常保存一份公开输入（x0、上下界、预算），同名就不报。代价是：如果真值和公开文件用同一个名字保存同一个答案，L2 会漏掉，只能靠 L1b/L3。
- **L4a 只能抓单调关系**：单测 `test_join_probe_limit_non_monotone` 记录了一个已知漏洞——p(1−p) 在 p 跨过 0.5 时不单调，抓不到。这类问题留给 L4b（廉价 agent 反解攻击，模型角色待定，当前跳过）。
- 正例只有 7 个，召回数字只说明这两类已知泄漏（公开 Oracle 对象、可逆协方差）能抓到，不代表其他泄漏类型的召回。
